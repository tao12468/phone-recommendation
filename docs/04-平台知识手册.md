## 1. 项目在做什么

这个项目要做的是一个 Web 系统：用户注册登录后，系统根据用户的预算、品牌偏好、使用场景等，推荐合适的手机。

核心特点是“数据驱动”：

```text
采集手机数据
   -> 清洗数据
   -> 计算特征
   -> 推荐手机
   -> 收集用户行为
   -> 更新用户偏好
   -> 再次推荐
```

这个循环就是“数据闭环”。

## 2. 整体架构

系统分为三层：

```text
浏览器前端（HTML + CSS + JavaScript）
        |
        | HTTP / JSON
        v
后端（Python + Flask）
        |
        | SQL
        v
数据库（MySQL）
```

前端只负责展示和交互，后端负责业务逻辑，数据库负责保存数据。

当前前端是原生 HTML/CSS/JS，后端是 Flask。开题报告里写的 Spring Boot + Vue 是正式方案，可以在后期替换。

## 5. 数据采集

数据来源是中关村在线手机频道。

爬虫文件：

```text
code/crawler/zol_spider.py
```

爬虫分两步：

第一步抓列表，得到手机名称、价格、详情页地址和图片地址：

```powershell
Set-Location code
..\.venv\Scripts\python.exe crawler\zol_spider.py list --max-pages 5 --brands 613,1795,1673,544,98,50840,55075,34645,35579,1434,55535,35005,55731,295,642 --out data\zol_phone_list.json
```

第二步根据列表抓参数页，得到屏幕、电池、CPU、内存等：

```powershell
..\.venv\Scripts\python.exe crawler\zol_spider.py details --list data\zol_phone_list.json --max-items 1000 --out data\phones_raw.json
```

关键概念：

- HTTP 请求：程序模拟浏览器访问网页
- User-Agent：告诉网站“我是浏览器”
- 反爬：网站限制爬虫，所以爬虫需要控制频率、处理重试
- 解析：用 BeautifulSoup 从 HTML 中取出需要的内容

## 6. 数据清洗与缺失值处理

清洗规则文件：

```text
code/data/clean_rules.py
```

缺失值填充文件：

```text
code/data/impute_missing.py
```

清洗做的事：

- 手机名称只保留型号，去掉宣传语
- 品牌补全
- 价格、屏幕、电池、内存、存储的范围检查
- CPU 文本清理
- 使用场景拆分
- 去重

缺失值处理策略：

```text
能确定的 -> 从名称或描述解析
解析不出 -> 同品牌中位数
同品牌没有 -> 全量中位数
```

这样既能填补空缺，又不会随意编造真实参数。

## 8. 特征工程

特征工程文件：

```text
code/algorithms/feature_engineering.py
```

生成特征入口：

```powershell
..\.venv\Scripts\python.exe -m data.build_features --password 123456
```

生成的特征包括：

- 价格档位：入门、中端、高端、旗舰
- 机型定位：K-Means 聚类
- 性能分：根据 CPU 和内存估算
- 性价比：性能与价格的关系
- 系统类型
- 核心数、分辨率、发布年份
- 使用场景标签
- 品牌编号

特征的作用：把“文字描述”变成“数字”，推荐算法才能计算。

## 9. 推荐算法

项目里现在有三种推荐算法。

### 9.1 基于内容过滤

文件：

```text
code/algorithms/content_recommender.py
```

原理：

```text
用户偏好（预算、品牌、场景、系统）
   vs
手机特征
   ->
匹配打分
```

它还会计算“相似手机”：把每款手机变成向量，用余弦相似度找出最像的手机。

### 9.2 基于用户的协同过滤

文件：

```text
code/algorithms/collaborative_recommender.py
```

原理：

```text
找到和你兴趣相似的用户
   ->
看他们喜欢什么
   ->
推荐给你
```

它把交互记录变成“用户-手机”矩阵，再计算用户之间的相似度。

### 9.3 混合推荐

文件：

```text
code/algorithms/hybrid_recommender.py
```

原理：

```text
内容过滤结果 + 协同过滤结果
   ->
归一化分数
   ->
加权融合
   ->
最终排序
```

新用户没有交互数据时，自动退化为纯内容过滤。

## 10. 行为反馈闭环

文件：

```text
code/algorithms/feedback_engine.py
code/data/preference_repository.py
```

用户发生浏览、点击、对比、收藏时，系统会：

1. 记录交互
2. 读取当前偏好
3. 用该手机的特征更新偏好

更新规则：

```text
预算、性能分：指数滑动平均
品牌、场景、系统：统计次数
```

这样用户用得越多，推荐越准确。

## 11. 用户注册登录

文件：

```text
code/data/user_repository.py
code/auth_utils.py
```

密码使用 BCrypt 加密，登录使用 JWT。

简单理解：

```text
BCrypt：把密码变成无法反推的密文
JWT：登录后发一张“数字通行证”，以后请求带着它
```

```text

12. 行为反馈更新偏好
13. 下一次推荐更准确
```

## 16. 学习路线建议

如果要从头学会这个项目，建议按这个顺序：

```text
第一步：先启动系统，点一遍页面
第二步：读 app.py，理解接口
第三步：读爬虫，理解数据从哪来
第四步：读清洗和特征工程，理解数据处理
第五步：读三个推荐算法，理解推荐
第六步：读反馈引擎，理解数据闭环
第七步：读用户系统和前端，理解完整流程
```

学习时不要一次看完，每看一个文件就问自己：

```text
它的输入是什么？
它做了什么？
它的输出是什么？
它被谁调用？
```

这样比单纯背代码更有用。
