## 七个核心模块

### 1. 多源用户偏好采集

要采集的偏好包括：

- 预算范围
- 品牌倾向
- 屏幕尺寸
- 拍照需求
- 电池续航
- 处理器性能
- 使用场景：游戏、办公、拍照
- 机型偏好：直板、折叠、大屏
- 操作系统偏好：安卓、iOS

实现方式：首次问卷 + 浏览、收藏、对比等隐式行为。

### 2. 手机数据管理

要管理的字段包括：

- 品牌
- 价格
- 屏幕
- 电池
- 摄像头
- 处理器
- 其他规格参数

处理流程：

- 爬虫采集
- 数据清洗
- 缺失值处理
- 异常值处理
- 构建增强特征向量
- 定期增量更新

### 3. 混合推荐算法

三种推荐策略：

- 基于内容过滤：用户偏好与手机特征匹配
- 协同过滤：分析相似用户群体
- 知识图谱：利用实体关系挖掘潜在机型

冷启动策略：

- 新用户采用热门推荐 + 快速问卷
- 新手机直接基于内容特征参与推荐
- 行为数据积累后逐步引入协同过滤与知识图谱

### 4. 用户行为反馈与特征更新

要记录的行为：

- 浏览
- 点击
- 收藏
- 对比

目标：形成“采集 → 推荐 → 反馈 → 优化”的数据闭环。

### 5. 后端服务

核心接口：

- 用户管理
- 手机查询
- 推荐获取
- 行为上报
- 收藏操作

### 6. Web 前端

核心页面：

- 注册登录
- 偏好问卷
- 推荐列表
- 手机详情
- 收藏夹
- 机型横向对比

### 7. 系统集成与部署

- 前后端整合
- 本地或云服务器部署
- 提供可访问的 Web 地址
- 便于演示与测试

## 预期目标

1. 完成一个可运行的 Web 系统
2. 生成合理、多样化的个性化推荐列表
3. 实现行为数据采集与偏好动态更新
4. 主要功能稳定并通过测试
5. 完成毕业论文与答辩准备

## 当前技术选型

前期先使用轻量技术快速跑通，后期迁移到正式技术栈：

| 模块 | 前期实现 | 后期正式方案 |
| --- | --- | --- |
| 后端 | Flask | Spring Boot |
| 前端 | HTML/CSS/JS | Vue.js + Element UI |
| 数据库 | SQLite | MySQL |
| 缓存 | 暂无 | Redis |
| 图数据库 | 关系表模拟 | Neo4j |
| 爬虫 | Requests + BeautifulSoup | Scrapy |
| 算法 | NumPy / scikit-learn | Spark MLlib 可扩展 |

## 可验收的最小系统

即使还没有正式技术栈，系统也应能完成：

- 新用户注册并填写偏好问卷
- 浏览手机列表和详情
- 获得个性化推荐
- 收藏和对比手机
- 系统记录行为并更新偏好
- 再次进入时推荐结果发生变化
